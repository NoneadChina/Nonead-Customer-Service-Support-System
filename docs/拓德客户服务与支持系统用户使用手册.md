## 1. 系统简介

**拓德客户服务与支持系统**（NoneadCSS）是一套面向企业的全渠道客户服务管理平台。系统将邮件工单、在线聊天、知识库、日历管理、工作流自动化等能力整合于统一的 Web 界面，帮助客服团队：

- **集中处理**：邮件、聊天、电话等多渠道客户请求统一为会话工单。
- **高效协作**：分配、转派、关注、内部备注、聊天 @提及，团队协作更顺畅。
- **智能响应**：工作流自动触发、宏命令一键执行、SLA 时限监控、日历提醒。
- **持续优化**：满意度评价、报表统计、审计日志、知识库沉淀驱动改进。
- **实时沟通**：基于 SignalR 的双向实时通信，支持消息撤回/编辑、已读回执、输入状态指示。
- **客户自助**：可嵌入第三方网站的客户聊天浮窗 Widget，客户无需登录即可咨询。
- **全渠道接入**：支持邮件、在线聊天、微信公众号、钉钉、飞书、WhatsApp Business、Facebook Messenger、Telegram、LINE、Apple 信息（iMessage）等多渠道统一接入，客户消息自动汇聚会话。
- **安全合规**：JWT + Refresh Token 双令牌认证、AES-GCM 敏感数据加密、CSRF 防护、CSP 安全策略、审计日志、病毒扫描等多层安全保障。
- **多语言支持**：内置简体中文与英文双语界面，支持动态翻译管理。

### 支持的角色

| 角色 | 说明 |
|------|------|
| 管理员（Admin） | 拥有所有功能与配置权限 |
| 客服主管（Supervisor） | 管理团队、查看报表、分配工单 |
| 客服专员（Agent） | 处理分配给自己的工单 |
| 只读用户（Viewer） | 仅查看会话与客户，不可修改 |

## 2. 登录与账户

### 2.1 登录系统

1. 打开浏览器，访问系统地址（例如 `http://localhost:5173`）。
2. 在登录页输入 **邮箱** 与 **密码**。
3. 点击「登录」按钮。

```
┌─────────────────────────────────────┐
│         拓德客户服务与支持系统        │
│                                     │
│   邮箱：  [admin@example.com       ] │
│   密码：  [                       ] │
│                                     │
│            [ 登录 ]                 │
│   忘记密码？     注册新账号          │
└─────────────────────────────────────┘
```

> 💡 首次部署的管理员账号通过环境变量 `ADMIN_EMAIL` / `ADMIN_PASSWORD` 配置（示例见 `admin@example.com`）。开发/演示环境缺失时会回退到演示凭据 `admin@example.com / ChangeMe!123`；非开发环境（`ASPNETCORE_ENVIRONMENT != Development`）缺失时系统将中止启动，拒绝使用默认凭据。登录后请尽快在「个人中心 → 账户安全」修改密码。

#### 登录安全机制

系统采用多项安全机制保护账户安全：

| 安全机制 | 说明 |
|----------|------|
| 登录失败锁定 | 连续输入错误密码 **5 次** 后，账户将被临时锁定 **15 分钟**，锁定期间无法登录 |
| 密码强度校验 | 新密码必须满足密码策略要求（最小长度、复杂度、弱密码字典检查等） |
| 令牌安全 | 采用 JWT + Refresh Token 双令牌机制，令牌过期后自动轮换，检测到异常使用立即撤销所有令牌 |

> ⚠️ 如果您的账户因多次登录失败被锁定，请等待 15 分钟后再尝试，或联系管理员解锁。

### 2.2 忘记密码

1. 在登录页点击「忘记密码？」。
2. 输入注册邮箱，系统将发送密码重置链接。
3. 点击邮件中的链接，设置新密码。

> 🔒 **安全提示**：
> - 重置密码成功后，您账户下所有其他已登录的设备会被自动登出，确保账户安全
> - 所有未使用的重置链接会立即失效，防止重复使用
> - 重置链接具有有效期，过期后请重新申请

### 2.3 注册账号

如管理员开启了注册功能，可在登录页点击「注册新账号」填写信息提交。注册账号默认为待激活状态，需管理员在「用户管理」中激活。

## 5. 会话管理

会话管理是客服日常工作的核心，所有客户请求（邮件、聊天、电话）都会汇聚会话。

### 5.1 会话列表

进入「服务台 → 会话管理」，可以看到会话列表：

```
┌──────────────────────────────────────────────────────────────┐
│  [全部] [未分配] [我的] [已分配] [已关闭] [垃圾邮件]    🔍搜索 │
├──────────────────────────────────────────────────────────────┤
│  ☐ │ #1001 │ 📧邮件 │ 客户A <a@test.com> │ 活跃   │ 2分钟前 │
│  ☐ │ #1002 │ 💬聊天 │ 客户B <b@test.com> │ 待处理 │ 10分钟前│
│  ☐ │ #1003 │ 📧邮件 │ 客户C <c@test.com> │ 已关闭 │ 1小时前 │
└──────────────────────────────────────────────────────────────┘
```

#### 会话来源快捷标签

每个会话在列表和详情页头部均显示**渠道来源徽章**，帮助客服一眼区分客户联系渠道：

| 来源徽章 | 图标 | 说明 | 会话归属 |
|---------|------|------|---------|
| 📧 邮件 | 橙色信封 | 传统邮件工单 | 对应邮箱 |
| 💬 聊天 | 绿色气泡 | 在线聊天 Widget | 系统邮箱 / 指定邮箱 |
| 💬 微信 | 绿色微信图标 | 微信公众号粉丝消息 | 微信关联邮箱 |
| 💬 WhatsApp | Meta 蓝色徽章 | WhatsApp Business 消息 | WhatsApp 关联邮箱 |
| 💬 钉钉 | 蓝色钉钉图标 | 钉钉企业内/外部联系人消息 | 钉钉关联邮箱 |
| 💬 飞书 | 青蓝飞书图标 | 飞书单聊/群聊消息 | 飞书关联邮箱 |

- 不同渠道会话支持的**回复窗口**不同（如微信 48h、WhatsApp 24h），详情页将显示窗口倒计时
- 若同一客户通过多个渠道联系，可在客户档案中**合并**多条客户档案，统一查看历史

#### 筛选与查找

- **文件夹标签**：点击顶部标签快速切换「全部 / 未分配 / 我的 / 已分配 / 已关闭 / 垃圾邮件」
- **搜索框**：输入关键词搜索主题、客户邮箱、工单号
- **邮箱筛选**：下拉选择特定邮箱
- **分页**：每页 10 条，底部可翻页

#### 批量操作

勾选会话前的复选框，底部出现批量操作栏：

- **批量分配**：将选中的会话分配给某客服
- **批量关闭**：一次性关闭多个会话
- **批量更新优先级**：统一调整选中会话的优先级
- **批量删除**：将选中的会话移至垃圾邮件（软删除）

> 💡 **批量操作结果反馈**：系统会显示批量操作的详细结果，包括成功数量、失败数量和具体失败原因，便于您快速了解操作结果。部分失败不影响其他成功的操作。

##### 批量删除与恢复

删除的会话不会立即永久删除，而是进入「垃圾邮件」文件夹（软删除）：

1. **查看已删除会话**：点击会话列表顶部的「垃圾邮件」标签
2. **恢复会话**：在垃圾邮件中选择会话，点击「恢复」按钮即可还原
3. **永久删除**：在垃圾邮件中选择「永久删除」将彻底删除数据，此操作不可撤销

> ⚠️ 永久删除操作不可恢复，请谨慎操作。建议先在垃圾邮件中确认后再执行永久删除。

#### 回复客户

1. 在底部输入框输入回复内容。
2. 可点击「快捷回复」选择预设话术。
3. 可点击「📎 上传附件」添加文件（支持图片、PDF、文档、压缩包等）。
4. 点击「发送」按钮将回复发送给客户。

#### 保存与恢复草稿

在输入回复内容时，可随时保存草稿：

- **保存草稿**：点击输入框下方的「保存草稿」按钮，系统会保存当前正文、抄送、密送和已上传的附件
- **自动恢复**：下次再进入该会话详情页时，草稿会自动回填到输入框中，无需手动操作
- **自动清理**：回复发送成功后，草稿会自动删除

> 草稿按会话粒度保存，每个会话独立保存一份草稿。

#### 附件安全

上传的附件和收到的邮件附件都会经过自动病毒扫描：

- **支持的格式**：图片（jpg/png/gif/bmp）、PDF、Office 文档（doc/docx/xls/xlsx/ppt/pptx）、文本、压缩包（zip/rar）
- **大小限制**：单文件不超过 20MB
- **安全检查**：自动检测恶意文件、可执行文件、扩展名欺骗，未通过安全检查的文件会被拒绝

#### 内部备注

点击「备注」切换到内部备注模式，备注仅团队内部可见，客户不可见。适用于：
- 记录处理进展
- 向其他客服交接信息
- 标注特殊注意事项

内部备注支持：
- **富文本格式**：支持加粗、列表、链接等格式
- **附件上传**：可在备注中添加附件文件，方便团队共享资料
- **发送人显示**：备注会显示创建人和创建时间，便于追溯

> 💡 内部备注与客户回复是分开的，客户无法看到任何内部备注内容，可放心记录内部沟通信息。

#### 分配与转派

- 点击右侧「分配」按钮，选择要分配的客服或团队。
- 已分配的会话可点击「取消分配」重新放回未分配池。

#### 关注会话

点击「关注」按钮可关注该会话，后续有新消息会收到通知。适用于：
- 主管关注重点工单
- 协作者跟踪处理进度

#### 管理标签

在右侧信息栏点击标签区域：
- **添加标签**：从已有标签中选择，或输入名称创建新标签
- **移除标签**：点击标签上的 × 号

#### 克隆会话

点击会话详情页顶部的「克隆」按钮，可以快速复制当前会话及其所有消息记录，生成一个新的会话副本。适用于：
- 基于历史工单快速创建类似的新工单
- 保留原会话记录的同时，在副本上继续处理新问题
- 培训或测试时复用典型会话场景

克隆规则说明：
- **客户消息**：保留原始客户信息（客户名称、客户邮箱、消息内容）
- **客服回复**：回复人更新为当前操作用户，消息内容保留
- **内部备注**：保留所有内部备注，方便参考历史处理思路
- **附件**：所有附件一并复制到新会话中
- **标签与分类**：继承原会话的标签、优先级等属性

> 克隆后的会话标题会自动添加「[副本]」标识，便于区分。

#### 关闭与重开会话

- 点击「关闭」按钮结束会话，系统可自动发送满意度评价邀请
- 已关闭的会话可在详情页点击「重新打开」恢复处理

## 6. 客户管理

### 6.1 客户列表

进入「服务台 → 客户管理」，查看所有客户：

```
┌──────────────────────────────────────────────────────────┐

#### 常见连接问题排查

| 错误信息 | 可能原因 | 解决方法 |
|----------|----------|----------|
| LOGIN Login error, user name or password error | 用户名或密码错误 | 1. 确认邮箱账号密码正确<br>2. 部分邮箱需使用「授权码」而非登录密码（如 QQ邮箱、163邮箱）<br>3. 开发环境：确认 `appsettings.Development.json` 中配置了固定加密密钥，否则重启后密码无法解密 |
| Connection refused | 无法连接服务器 | 1. 检查主机地址和端口<br>2. 确认网络连通性<br>3. 检查防火墙设置 |
| SSL/TLS handshake failed | 加密连接失败 | 1. 确认 SSL/TLS 开关设置正确<br>2. 检查端口是否匹配（IMAP SSL 通常 993，SMTP TLS 通常 587） |

> ⚠️ **开发环境注意事项**：如果您在本地开发环境中测试邮箱连接，务必在 `appsettings.Development.json` 中配置固定的加密密钥。否则系统每次重启会生成新密钥，导致之前保存的密码无法解密，出现「用户名或密码错误」的假象。配置方式请参考开发文档。

## 9. 自动化

### 9.1 工作流自动化

工作流在特定事件触发时，自动执行预设动作，减少人工操作。

#### 触发器类型

| 触发器 | 说明 |
|--------|------|
| 新会话创建 | 新会话到达时触发 |
| 收到新回复 | 客户回复会话时触发（仅客户回复，不包括客服回复） |
| 客服回复 | 客服回复会话时触发 |
| 状态变更 | 会话状态变化时触发 |
| 分配变更 | 会话被分配或改派时触发 |
| 会话关闭 | 会话状态变更为已关闭时触发 |
| 会话重新打开 | 已关闭会话被重新打开时触发 |
| 标签添加 | 为会话添加标签时触发 |
| 标签移除 | 从会话移除标签时触发 |
| 满意度评价提交 | 客户提交满意度评价时触发 |
| 添加内部备注 | 客服添加内部备注时触发 |
| 优先级变更 | 会话优先级变化时触发 |

#### 动作类型

| 动作 | 说明 |
|------|------|
| 分配给 | 自动分配给指定客服或团队 |
| 设置状态 | 变更会话状态 |
| 设置优先级 | 调整会话优先级 |
| 添加标签 / 移除标签 | 管理会话标签 |
| 添加内部备注 | 添加内部备注 |
| 发送回复 | 自动回复客户 |
| 发送邮件 | 通过自定义邮件模板发送邮件 |
| 触发 Webhook | 调用外部接口 |
| 执行宏 | 执行预设的宏，一次性运行多步操作 |

> 💡 **执行宏动作**：可在工作流中调用已创建的宏，将宏中的所有动作作为一个整体执行。适用于需要多步操作的复杂自动化场景，例如「关闭工单 + 发送满意度邀请 + 标记已解决标签」可通过一个宏动作完成。

#### 创建工作流

1. 进入「自动化 → 工作流自动化」
2. 点击「+ 新建工作流」
3. 配置触发器（选择触发时机）
4. 配置条件（可选）：设置匹配条件，只有满足条件的会话才会执行动作

```
当 [主题] [包含] [退款]
且 [邮箱] [等于] [support@company.com]
```

5. 配置动作：选择一个或多个要自动执行的动作
6. 点击「保存」并启用工作流

#### 默认工作流

系统内置以下工作流，默认全部启用：

| 工作流名称 | 触发器 | 说明 |
|-----------|--------|------|
| 客户回复确认邮件 | 收到客户回复 | 自动向客户发送"已收到回复"确认邮件 |
| 紧急工单邮件通知 | 新会话创建 | 主题含"紧急/急"时，自动分配给管理员并发送 SLA 告警邮件 |
| 新会话客户回访邮件 | 新会话创建 | 新会话创建后自动发送回访邮件 |
| 会话升级通知邮件 | 新会话创建 | 主题含"升级/投诉/emergency"时，自动升级并通知管理员 |
| 满意度评价感谢邮件 | 满意度评价提交 | 客户提交评价后，自动发送感谢邮件 |
| 新会话自动分配 | 新会话创建 | 按轮询方式自动分配给客服 |

> 可在工作流列表中手动启用/禁用各工作流。

### 9.2 SLA 策略

SLA（服务等级协议）用于监控会话的响应与解决时效。

#### 创建 SLA 策略

1. 进入「自动化 → SLA 策略」
2. 点击「+ 新建策略」
3. 配置：
   - **策略名称**：如「标准 SLA」
   - **首次响应时间**：如 2 小时
   - **解决时间**：如 24 小时
   - **适用邮箱**：选择关联的邮箱
   - **适用标签**：可按标签细粒度匹配
4. 保存后启用

> ⚠️ 超出 SLA 时限的会话将在仪表盘中高亮提醒，并可通过通知规则发送告警。

### 9.3 宏管理

宏是一组预设操作的集合，可一键执行多步操作，大幅提升客服处理效率。

#### 宏的使用场景

- **标准化处理流程**：将常用的多步操作（如关闭工单 + 发送回复 + 添加标签）保存为宏
- **批量处理**：配合工作流自动化，对一批会话自动执行宏操作
- **新人培训**：将标准回复流程封装为宏，新人直接调用即可

#### 支持的动作类型

宏支持以下动作，可自由组合：

| 动作 | 说明 | 值配置 |
|------|------|--------|
| 设置状态 | 变更会话状态 | 下拉选择：活跃 / 待处理 / 已关闭 / 垃圾邮件 |
| 设置优先级 | 调整会话优先级 | 下拉选择：低 / 中 / 高 / 紧急 |
| 分配给 | 分配给指定客服或团队 | 下拉选择用户或团队 |
| 添加标签 | 为会话添加标签 | 选择已有标签 |
| 移除标签 | 移除会话的指定标签 | 选择已有标签 |
| 发送回复 | 自动回复客户 | 填写回复内容 |
| 添加内部备注 | 添加内部备注 | 填写备注内容 |

#### 创建宏

1. 进入「自动化 → 宏管理」
2. 点击「+ 新建宏」
3. 填写宏名称（如「关闭并标记已解决」）
4. 点击「+ 添加动作」，从下拉菜单选择动作类型
5. 根据动作类型配置对应的值（有预设选项的动作用下拉菜单选择）
6. 可添加多个动作，按顺序执行
7. 点击「保存」

#### 编辑宏

在宏列表中点击「编辑」，可修改宏的名称和动作组合：
- 添加新动作
- 删除已有动作
- 调整动作执行顺序
- 修改动作的参数值

#### 使用宏

**方式一：会话详情页单会话执行**
1. 进入会话详情页
2. 点击「执行宏」按钮
3. 选择要执行的宏
4. 系统自动按顺序执行宏中的所有动作

**方式二：工作流自动化批量执行**
1. 进入「自动化 → 工作流自动化」
2. 创建或编辑工作流
3. 在动作中选择「执行宏」
4. 选择目标宏
5. 工作流触发时，会自动对匹配的会话执行该宏

> 💡 **宏与工作流配合**：将复杂的多步操作封装为宏，再通过工作流按条件触发，可实现完全自动化的工单处理流程。例如：新工单创建时自动识别类型 → 执行对应宏（分配 + 标记标签 + 发送自动回复）。

| 任务（task） | 🔵 蓝色 | 待办事项 | 优先级、进度（0-100）、子任务 |
| 会议（meeting） | 🟣 紫色 | 团队会议、客户会议 | 地点、会议链接、参会人 |
| 提醒（reminder） | 🟡 琥珀色 | 自定义提醒 | 关联事件 ID |

#### 事件状态

| 状态 | 颜色 | 说明 |
|------|------|------|
| 待处理（pending） | 🟡 琥珀色 | 新创建的默认状态 |
| 已完成（completed） | 🟢 绿色 | 已处理完毕 |
| 已取消（cancelled） | ⚪ 灰色 | 不再执行 |

状态转换规则：`pending` 可转为 `completed` 或 `cancelled`；`completed` 和 `cancelled` 可转回 `pending`。

#### 创建事件

1. 点击日历上的日期或「+ 新建事件」
2. 填写基本信息：
   - **标题**（必填，最长 200 字符）
   - **类型**：截止日期 / 任务 / 会议 / 提醒
   - **开始时间 / 结束时间**（必填）
   - **全天事件**：勾选后忽略具体时间
   - **关联邮箱**（可选）：用于权限隔离
   - **关联会话**（可选）：绑定到工单
   - **负责人**（可选）：分配给指定客服
   - **描述**（最长 5000 字符）
   - **颜色标记**：8 种预设颜色
3. 根据事件类型填写专属字段：
   - **任务/截止日期**：优先级（1-5）、进度（0-100）
   - **截止时间（dueAt）**：任务类型（`task`）专属字段，表示任务的实际截止时间，与「结束时间」（endAt）相互独立。默认跟随 endAt，用户修改后保持独立值；切换事件类型时自动清理非专属字段
   - **会议**：地点（最长 200 字符）、会议链接（最长 500 字符，仅允许 http/https/zoommtg/teams/tel/mailto 协议）、参会人（多选用户）
   - **任务**：子任务列表（JSON 数组）
   - **提醒**：关联事件 ID
4. 保存

> 💡 **创建者权限**：事件创建后，创建者（`CreatedBy`）始终拥有编辑/删除权限，即使将事件分配给了其他客服。这确保了专员可以管理自己创建的事件。

#### 与会者管理

会议类型事件支持添加与会者，系统会自动聚合邮箱用于邮件提醒。

**添加与会者**：
- 在「与会者」输入框输入邮箱地址，按回车或点击「+」添加
- 支持一次添加多个邮箱（逗号/分号/空格分隔）
- 添加后输入框自动保持焦点，便于连续添加

**邮箱校验**：
- 系统使用正则 `/^[^\s@]+@[^\s@]+\.[^\s@]+$/` 校验邮箱格式
- 全部无效时提示"邮箱格式不正确"
- 部分无效时只添加有效邮箱，并提示"N 个邮箱格式不正确已忽略"
- 列表顶部显示"N 位与会者"，并提供「清空」按钮一键移除全部

#### 重复日程

支持四种重复类型，适合周期性会议、定期任务等场景：

| 重复类型 | 说明 | 示例 |
|---------|------|------|
| 每日 | 每 N 天重复 | 每日站会（间隔 1） |
| 每周 | 每 N 周重复 | 周报会议（间隔 1） |
| 每月 | 每 N 月重复 | 月度复盘（间隔 1） |
| 每年 | 每 N 年重复 | 年度评审（间隔 1） |

**结束方式**（二选一）：
- **结束日期**：指定重复日程的结束日期
- **重复次数**：指定重复 N 次（范围 1-1000）

**中文描述预览**：

选择重复规则后，编辑器底部会实时显示中文描述，例如：
- 每日重复：`每 1 天重复`
- 每周重复 + 工作日：`每 1 周重复，周一至周五`
- 每月重复 4 次：`每 1 月重复，共 4 次`
- 每年重复到指定日期：`每 1 年重复，至 2026-12-31 结束`

> 💡 中文描述根据表单的重复类型、间隔、工作日选择、结束方式自动生成，保存时系统据此生成标准 RRULE，无需手动编写。

**工作日快捷按钮**（仅「每周」重复类型显示）：

| 按钮 | 说明 |
|------|------|
| 工作日 | 一键勾选周一至周五 |
| 每天 | 一键勾选周一至周日 |
| 清除 | 清空所有工作日勾选 |

**排除日期**：
- 可手动排除特定日期的实例（如节假日）
- 可手动添加额外日期（如临时加班）
- 通过日期选择器管理排除/额外日期列表

**展开上限**（防止性能问题）：
- 单事件最大实例数：365（可配置 `Calendar:MaxRecurrenceInstances`）
- 全局展开上限：5000（可配置 `Calendar:MaxExpandedInstances`）

**更新/删除模式**：

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| 仅本次（single） | 只修改/删除当前实例，不影响其他 | 临时调整某一次会议 |
| 本次及后续（following） | 修改/删除当前及之后的所有实例 | 计划变更，历史保留 |
| 全部（all） | 修改/删除所有实例（含历史） | 规则整体调整 |

> 💡 「仅本次」会创建一个独立实例；「本次及后续」会截断原父事件的结束日期，并新建一个父事件。

#### 提醒功能

事件支持多通道提醒，确保不会错过重要事项。

**提醒类型选择**：

新建/编辑事件时，可在「提醒设置」区域选择提醒渠道：

| 提醒类型 | 说明 | 适用场景 |
|---------|------|---------|
| 站内通知 | 推送给负责人和参会人 | 日常协作，无需打扰外部 |
| 邮件通知 | 发送到所有收件人邮箱 | 跨团队、跨时区的重要事项 |
| 短信通知 | 发送到预留手机号（v2.2.8：短信网关未实现，自动降级为站内通知） | 关键 SLA、紧急任务到期 |

> 💡 切换提醒类型时会自动清空原有提醒时间设置，请重新选择提醒时间。
>
> 📝 **v2.2.8 提醒行为优化（T000090）**：
> - **全局提醒监听**：v2.2.7 及之前版本仅在 `/calendar` 页面监听提醒，离开页面后提醒丢失。v2.2.8 新增 `GlobalCalendarReminderListener` 全局组件，挂在 `App.tsx` 顶层，**任意页面**均可接收提醒弹窗。
> - **按类型分发**：后端 `CalendarReminderService` 现按 `ReminderType` 精确分发通知，不再对所有类型一并发送站内+邮件。
> - **短信降级**：选择「短信通知」时，因短信网关尚未接入，系统自动降级为站内通知，不影响提醒触达。
> - **查看详情跳转**：提醒弹窗点击「查看详情」会跳转到 `/calendar?focusEventId=N`，自动展开对应事件详情抽屉，并完成 ACK 确认（v2.2.8 修复导航时 ACK 丢失问题）。

**提醒时间**：
- 预设选项：准时、5 分钟、15 分钟、30 分钟、1 小时、1 天、1 周
- 自定义范围：0-525600 分钟（最长一年）
- 自定义输入框支持分钟数输入，并自动显示"≈ X 天 Y 小时"换算提示

**提醒收件人**（自动聚合）：
- 事件创建者
- 负责人（UserId）
- 参会人（AttendeesJson 中的用户）
- 额外邮件地址（ReminderEmails，逗号/分号/换行分隔，最长 1000 字符）

> ⚠️ 选择「邮件通知」但未添加与会人时，系统会显示警告提示，建议先添加至少一位与会者再启用邮件提醒。

**提醒渠道**：
- **站内通知**：推送给负责人和参会人
- **邮件通知**：发送到上述所有收件人

**邮件模板**：
- 优先使用数据库模板（slug: `calendar-reminder`，需 IsActive）
- 模板缺失时使用内置兜底 HTML 模板
- 支持变量：`{{event_title}}`、`{{event_type}}`、`{{event_start_time}}`、`{{event_location}}`、`{{event_meeting_url}}` 等

**发件邮箱选择**：
- 优先使用事件关联的邮箱（需 IsActive 且未删除）
- 回退到第一个活跃的全局默认邮箱

**周期性事件提醒**：
- 每个周期会重置提醒状态（通过 `LastReminderSentAt` 判断）
- 原子标记防重复：多实例环境下只有一个实例能标记成功

**扫描窗口**：未来 1 小时内的事件。

#### 垃圾箱与回收站

删除事件采用软删除机制，可在垃圾箱中恢复：

- **查看垃圾箱**：仅超级管理员可访问「日历管理 → 垃圾箱」
- **恢复事件**：校验父事件是否已恢复，若父事件已删除则恢复失败
- **永久删除**：级联清理 Outlook 映射和子实例，不可恢复
- **清空垃圾箱**：一键清空所有已删除事件
- **按保留期清理**：自动清理超过指定天数（默认 30 天）的已删除事件

#### ICS 导入导出

**导出**：
- 单事件导出：点击事件详情页的「导出」按钮，下载 .ics 文件
- 范围导出：选择日期范围批量导出，支持邮箱筛选
- 导出格式：RFC 5545 标准 .ics 文件
- 导出原始事件（不展开重复实例），避免重复

**导入**：
- 上传 .ics 文件（最大 10MB，仅 .ics 扩展名）
- 系统解析后批量导入
- 返回 `{ imported, skipped }` 统计

#### 日历订阅

支持通过 HMAC Token 鉴权的订阅 URL，可在外部日历应用中订阅：

1. 进入「日历管理」，点击「获取订阅链接」
2. 系统生成专属订阅 URL（含 Token）
3. 将 URL 复制到 Outlook / Google Calendar / Apple Calendar 等应用的「订阅日历」功能中

**Token 机制**：
- 格式：`userId.version.expiresAt.hash`（4 段式 HMAC 签名）
- 默认有效期：365 天
- 吊销机制：用户记录变更后（`UpdatedAt.Ticks`），旧 Token 立即失效
- 恒定时间比较：防止时序攻击

> ⚠️ 订阅 URL 包含个人 Token，请勿分享给他人。Token 过期或被吊销后需重新获取。

#### Outlook 同步

支持与 Microsoft Outlook 日历的双向同步：

**配置步骤**：
1. 进入「日历管理 → Outlook 同步」
2. 点击「连接 Outlook 账户」，跳转到微软 OAuth 授权页
3. 授权后自动回调并保存令牌（加密存储）
4. 选择同步方向：
   - **双向同步（both）**：默认，双向同步变更
   - **仅推送到 Outlook（to_outlook）**：系统 → Outlook
   - **仅从 Outlook 拉取（from_outlook）**：Outlook → 系统
5. 启用同步

**安全机制**：
- OAuth 会话 Cookie（10 分钟 TTL，一次性使用）
- Cookie 值加密存储，回调时二次校验 userId
- AccessToken / RefreshToken 加密存储
- 防 CSRF 攻击

**手动同步**：点击「立即同步」按钮触发（限流保护）。
**断开连接**：清除令牌，保留设置（可重新连接）。

#### 乐观锁

事件使用 `RowVersion` 乐观锁，防止并发更新覆盖。如果两人同时编辑同一事件，后保存者会收到冲突提示，需刷新后重试。

#### 实时通知

事件创建/更新/删除时，系统通过 SignalR 向创建者、负责人、参会人推送实时通知，相关用户的界面会自动刷新。

**SignalR 重连与刷新**：
- 网络恢复后 SignalR 自动重连，并触发一次全量数据刷新，避免重连期间错过的消息丢失；
- 标签页切到后台后连接断开，切回前台时自动重连；
- undo/redo 操作失败时会自动回滚乐观修改，保持 UI 与后端一致。

月/周/日视图的日期网格中，鼠标悬停事件色块时会显示弹窗：

│  14:00-15:00 · 创建者: 张三      │
│  产品需求评审会议                │
└──────────────────────────────────┘
```

弹窗内容：
- **时间区间**：开始时间 - 结束时间
- **创建者名称**：取自 `createdByName` 字段
- **事件标题**：完整标题

#### 分类管理

切换到「分类管理」标签页管理知识库分类树。

**分类特性**：
- **多级树形结构**：通过父分类实现层级（如「产品 → 安装 → 常见问题」），支持无限层级
- **递归深度保护**：最大递归深度 16 级，防止恶意构造超深分类树导致栈溢出
- **循环引用校验**：更新分类时自动检测，禁止将分类设为自身或后代的子分类
- **邮箱归属**：分类可关联到特定邮箱（仅该邮箱成员可见）或设为「通用」（所有用户可见）
- **排序值**：支持自定义排序，数值小的排在前面
- **图标**：支持自定义 emoji 图标，预设 16 个常用图标（📚 📘 📖 📄 📝 💡 🔧 ⚙️ 等）
- **启用/禁用**：禁用后分类仍存在，但不会出现在文章分类下拉选项中

**新建分类**：

1. 点击「+ 新建分类」按钮
2. 填写：
   - **分类名称**（必填，最长 100 字符）
   - **父分类**：选择上级分类，或选「无（顶级分类）」
   - **描述**（最长 500 字符）
   - **图标**：选择预设 emoji 或自定义文本
   - **所属邮箱**：选择「通用（所有邮箱）」或具体邮箱
   - **排序值**：数值越小越靠前
   - **启用此分类**：勾选框
3. 点击「保存」

切换到「时间记录」Tab 可管理所有工时条目：

- **筛选**：支持按描述/工单号搜索、类型（计时器/手动录入）、计费状态、日期范围筛选
- **列表字段**：类型徽章、描述、关联工单号/客户、用户、起止时间、时长、可计费标记
- **操作**：每行可编辑或删除（删除为软删除，可在回收站恢复）
- **分页**：每页 10 条

#### 新建/编辑记录

点击「新建记录」或在列表中点击「编辑」，弹出模态框：

- **类型**：计时器（timer）或手动录入（manual）
- **描述**：必填
- **关联工单**：下拉菜单，自动载入状态为"活跃"的会话，选项格式为 `#会话ID - 主题内容 - 客户姓名`；选中后自动联动填充关联客户
- **关联客户**：下拉菜单，载入客户列表，选项格式为 `#客户ID - 客户姓名`；可手动修改联动填充的值
- **开始时间**：必填
- **时长（分钟）**：手动录入必填，支持快捷预设（15/30/60/90/120/240 分钟）
- **是否可计费**：勾选后该条工时计入可计费统计

> 💡 v2.2.6 升级：关联工单和关联客户从手动输入数字 ID 改为下拉菜单，选择工单后自动填充客户，无需手动查找客户 ID。

#### 数据导出

点击页面右上角「导出 CSV」按钮，按当前筛选条件导出工时记录，文件含 UTF-8 BOM 防止 Excel 中文乱码，字段包括 ID、类型、描述、工单号、客户、用户、起止时间、时长、可计费标记。

#### 权限说明

- **超级管理员**：可见全部用户的时间记录
- **主管**：可见自己及所有客服/只读用户的记录
- **客服/只读**：仅可见本人记录

#### 回收站

删除的时间记录可在回收站中恢复或永久删除（清空），永久删除不可恢复。

#### 会话状态

| 状态 | 中文标签 | 说明 |
|------|----------|------|
| `waiting` | 等待接待 | 客户发起聊天后的初始状态 |
| `active` | 进行中 | 客服接待或发送首条消息后 |
| `closed` | 已关闭 | 客服或客户主动关闭 |
| `transferred` | 已转工单 | 转工单后，关联工单 ID |

状态转换：
- 等待 → 进行中（客服接待或发送消息）
- 任意 → 已关闭（客服或客户关闭）
- 任意 → 已转工单（转工单操作）

#### 接待客户

1. 在会话列表点击「等待中」的会话，或点击「接待」按钮
2. 系统自动将会话状态改为「进行中」，并插入系统消息「客服 XX 已接入对话」
3. 在底部输入框输入消息，按 Enter 发送（Shift+Enter 换行）
4. 可查看客户信息（邮箱、IP、客户 ID 等）
5. 处理完毕点击「关闭会话」

#### 消息功能

**发送消息**：
- 在输入框输入文本，按 Enter 发送
- 支持表情、@提及、快捷回复、附件上传

**消息撤回**：
- 仅可撤回自己发送的消息
- **2 分钟时间窗**：发送后 2 分钟内可撤回，超时不可撤回
- 撤回后双方看到「XX 撤回了一条消息」提示
- 操作方式：点击消息气泡的「更多操作」菜单 → 「撤回」

**消息编辑**：
- 仅可编辑自己发送的消息
- 已撤回的消息不可编辑
- 无时间限制，随时可编辑
- 编辑方式：点击消息气泡的「更多操作」菜单 → 「编辑」
- 进入内联编辑模式（textarea），Enter 保存 / Esc 取消 / Shift+Enter 换行
- 编辑后显示「已编辑」标记（hover 显示编辑时间）

**已读回执**：
- 客服发送的消息显示已读状态：
  - ✅ 已读：蓝色双勾（hover 显示已读时间）
  - ✓ 未读：灰色单勾
- 客户发送的消息在客服侧标记已读后，客户侧显示「已读」文字

**输入状态指示**：
- 当对方正在输入时，显示「XX 正在输入...」+ 三点跳动动画
- 3 秒超时后自动隐藏
- 输入状态推送有 2 秒节流，避免频繁请求

**复制消息**：
- hover 消息气泡显示复制按钮
- 点击复制消息内容到剪贴板
- 复制成功显示对勾反馈

**附件分享**：
- 点击输入框左侧的 📎 按钮上传附件
- 支持拖拽上传
- **大小限制**：单文件不超过 25MB
- **支持格式**：图片（jpg/png/gif/webp/bmp/svg）、PDF、Word/Excel/PPT、文本、CSV、压缩包
- 图片附件内嵌预览（点击可放大），文件附件显示下载链接

**消息搜索**：
- 在对话区点击搜索图标，输入关键词
- 匹配消息高亮显示（黄色标记）
- 显示匹配数量（N/M），支持上一个/下一个导航

#### @提及功能

客服侧支持在消息中 @提及同事，被提及的客服会收到通知。

**使用方式**：
1. 在输入框中输入 `@`（需在行首或空格后，避免误匹配邮箱地址）
2. 输入同事姓名或邮箱关键词
3. 系统显示候选列表（最多 8 条），按姓名/邮箱模糊匹配
4. 使用 ↑↓ 键选择，Enter 或 Tab 确认，Esc 取消
5. 选中后插入 `@[姓名] ` 格式（含尾随空格）

**提及渲染**：
- 消息中的 `@[姓名]` 渲染为蓝色高亮标签 `@姓名`
- 客服消息：半透明白色背景
- 客户消息：蓝色背景

**提及通知**：
- 被提及的客服（排除发送者自己）会收到 `ChatMention` 事件
- 通知内容包含：会话 ID、被提及用户、发送者、消息预览（前 100 字符）
- 客服端显示 Toast 通知：「XX 在聊天中 @了你：消息预览」
- 点击通知可跳转到对应会话
- 通知发送失败不影响主消息发送（静默处理）

> 💡 @提及功能仅客服侧可用，客户侧无法创建提及，但可以看到提及高亮渲染。

#### 快捷回复

客服侧支持快捷回复功能，快速插入预设话术：

1. 点击输入框左侧的 ⚡ 按钮打开快捷回复面板
2. 面板按当前会话所属邮箱过滤
3. 支持搜索快捷回复
4. 点击选中后内容追加到输入框（含换行）
5. 与表情面板互斥显示

> 💡 快捷回复内容在「邮件中心 → 快捷回复」中管理。

#### 表情支持

- 点击输入框左侧的 😊 按钮打开表情面板
- 提供 24 个常用表情
- 点击表情追加到输入框
- 与快捷回复面板互斥显示

#### 转工单

将会话转为邮件工单，便于后续跟进：

1. 在对话区点击「转工单」按钮
2. 在弹出的模态窗中填写：
   - **目标邮箱**（可选，留空使用原邮箱）
   - **分配客服**（可选，留空自动分配）
   - **工单主题**（可选，留空自动生成）
3. 确认后系统执行：
   - 拼接完整聊天记录（含客户信息、主题、时间、所有消息）
   - 按客户邮箱创建或关联客户档案
   - 创建工单（Conversation），类型为 Chat
   - 创建工单线程（Thread）保存聊天记录
   - 更新会话状态为「已转工单」，关联工单 ID
   - 插入系统消息「会话已转为工单 #XX」
4. 信息面板显示关联工单链接，点击可跳转到工单详情页

└──────────────────────────────┘
```

点击「开始新的咨询」重置到发起表单阶段。

#### 客户侧特性

**无需登录**：
- 客户无需注册或登录即可使用 Widget
- 基于 `sessionToken`（32 位字母数字）匿名鉴权
- 所有客户侧 API 端点均 `[AllowAnonymous]`

**安全机制**：
- **sessionToken 校验**：长度至少 32 字符，仅允许字母数字，不合法返回 404，防止暴力枚举
- **限流保护**：每 IP 每分钟最多 30 次请求（滑动窗口限流）
- **SignalR 鉴权**：连接 ChatHub 时通过 query string 传递 sessionToken，服务端校验会话合法性

**实时通信**：
- 基于 SignalR 双向实时通信
- 监听事件：新消息、消息撤回、消息编辑、已读回执、输入状态
- **降级策略**：SignalR 未连接时降级为 HTTP 轮询刷新消息列表

**连接状态指示**：
- 🟢 已连接：正常实时通信
- 🟡 连接中：正在建立连接
- 🟡 重连中：连接断开后自动重连
- 🔴 已断开：连接失败，降级为轮询

#### SignalR 实时事件

| 事件 | 触发场景 | 推送目标 |
|------|----------|----------|
| `RealtimeChat` | 新消息发送（客服/客户） | 客服端 + 客户会话组 |
| `ChatMessageRecalled` | 消息撤回 | 客服端 + 客户会话组 |
| `ChatMessageEdited` | 消息编辑 | 客服端 + 客户会话组 |
| `ChatMessageRead` | 标记已读 | 客服端 + 客户会话组 |
| `ChatTyping` | 输入状态 | 客服端（客户输入时）/ 客户会话组（客服输入时） |
| `ChatMention` | @提及 | 被提及的客服用户 |

### 11.6 微信公众号客服

微信公众号客服模块将微信公众号的粉丝消息接入到 NoneadCSS，客服可直接在系统中回复粉丝留言，消息实时双向同步，所有历史记录留存在系统中。

#### 11.6.1 微信设置（系统管理员）

在「系统管理 → 模块管理」中确保「微信」模块已启用，然后进入「功能模块 → 微信」进行配置。页面包含 4 个 Tab：

| Tab | 说明 |
|-----|------|
| **基础配置** | 填写 AppID、AppSecret、Token、EncodingAESKey；选择消息加解密模式（明文/兼容/安全加密模式）；保存后点击「测试连接」验证签名校验与回调连通性 |
| **状态监控** | 显示 AccessToken 有效状态/剩余有效时间、最近一次推送事件时间、待接入消息数；支持「手动刷新令牌」 |
| **通知消息** | 管理微信通知类消息触达：模板消息（旧版）与订阅通知（新版）双模式切换；会话搜索选择器、常用模板预设、实时 JSON 校验与卡片预览、发送历史记录（详见 11.6.5） |
| **自定义菜单** | 管理公众号底部菜单：可视化编辑器 + JSON 双向同步 + 手机预览 + Schema 校验（详见 11.6.6） |

**接入步骤**：

1. 登录微信公众平台，进入「开发 → 基本配置」
2. 记录 AppID 和 AppSecret，填入系统基础配置
3. 自定义 Token（随机字符串，至少 8 位），填入系统基础配置
4. 选择加解密模式；如启用安全加密模式，需要生成 EncodingAESKey（43 位字母数字组合）
5. 回到微信公众平台，点击「修改配置」
6. 服务器地址 URL：`https://{你的域名}/api/wechat`（注意必须是 HTTPS 公网可访问）
7. Token：与第 3 步一致
8. EncodingAESKey：与第 4 步一致
9. 选择消息加解密模式并提交
10. 回到系统「状态监控」，确认 AccessToken 有效，点击「测试签名校验」与「测试回调」两个按钮，全部打勾表示成功

> 💡 接入前确保服务器配置了正确的 HTTPS 证书，端口 80/443 对外可访问；微信回调会校验域名、签名和消息格式。

#### 11.6.2 接收微信消息

接入成功后，粉丝的以下消息会自动进入系统：

- **文本消息**：粉丝在公众号输入框发送文字，直接创建会话
- **图片消息**：自动下载图片素材，作为附件保存
- **语音消息**：自动下载 voice 素材，播放器内联播放
- **视频消息**：自动下载 video 素材，内联播放器展开观看
- **链接消息**：解析标题/描述/链接
- **关注/取消关注事件**：subscribe 事件触发欢迎语被动回复；unsubscribe 事件记录到客户档案
- **菜单点击/跳转事件**：记录到线程历史

**客户档案自动建档**：收到新粉丝消息后，系统自动调用「获取用户基本信息」接口（scope=snsapi_userinfo）提取：
- 昵称、头像、性别、语言
- OpenID（写入客户档案 channelId 字段，作为微信唯一标识）
- UnionID（存在时写入，供多应用合并）
- 所在地区、关注时间

后续同一粉丝再次发消息会按 OpenID 匹配到同一客户，支持多渠道合并同一客户档案。

#### 11.6.3 回复微信消息（客服）

在「会话详情」中，客户来源标识为「**微信**」（绿色徽章 + MessageCircle 图标）时，页面会使用微信专用回复框 `WeChatReplyBox`：

- **文本回复**：输入文本后点击「发送」，系统自动走客服消息（`/cgi-bin/message/custom/send`）接口推送
- **图片/语音/视频回复**：直接拖拽文件到回复框（或点击附件按钮选择），系统自动上传临时素材（media_id 3 天有效），然后调用对应类型的客服消息接口发送。大小限制：图片/语音 ≤ 2MB，视频 ≤ 10MB
- **表情面板**：点击 😊 按钮展开 24 个常用表情，Esc 可关闭
- **快捷回复**：按邮箱过滤的预设回复，支持搜索，插入后可继续编辑
- **快捷键面板**：查看键盘快捷键（Ctrl+Enter 发送、Esc 关闭浮层等）

#### 11.6.4 48 小时客服消息窗口

根据微信规则，自粉丝最后一次互动（发送消息、点击菜单、关注、扫描二维码等）起的 **48 小时**内，客服可自由通过客服消息接口发送任意内容；超过 48 小时后，客服消息会被微信拒绝。

在会话详情页顶部，以彩色进度条直观展示窗口状态：

| 状态 | 颜色 | 剩余时间 | 说明 |
|------|------|----------|------|
| ✅ ok | 绿色渐变 | > 12 小时 | 可自由发送客服消息 |
| ⚠️ warning | 琥珀色渐变 | ≤ 12 小时 | 临近过期，建议尽快回复 |
| ❌ expired | 红色 | 已过期 | 客服消息无法送达，页面显示「前往模板消息」按钮跳转兜底 |

> 💡 进度条会自动定时刷新：正常态每分钟更新一次，剩余 < 1 小时时每秒更新显示秒级倒计时。

#### 11.6.5 通知消息（模板消息 + 订阅通知）

当客服消息窗口过期时，可使用通知类消息兜底联系客户。通知消息是微信提供的、无论客户多久未互动都可推送的通知类消息（仅限指定模板，不能发送营销内容）。系统支持两种触达模式：

| 模式 | API | 适用场景 |
|------|-----|----------|
| **模板消息（旧版）** | `message/template/send` | 服务号已申请模板消息权限，模板 ID 在微信公众平台「模板库」中添加 |
| **订阅通知（新版）** | `cgi-bin/message/subscribe/send` | 已配置订阅通知模板，客户主动订阅后可一次性触达（微信推荐方向） |

页面顶部模式切换按钮独立选择触达方式，两种模式互不干扰，按微信运营规则选择即可。

**会话搜索选择器**：选择目标客户时无需手动输入会话 ID，在搜索框输入关键词（标题/客户名/预览文本模糊匹配），下拉列表自动展示匹配的微信会话（会话 ID + 客户名 + 最近消息预览），单击选中即自动填入会话 ID。

**常用模板预设**：内置 3 个常用模板，一键填充模板 ID 和字段值，降低操作成本：
- 工单受理通知（标题/受理内容/受理时间/客服姓名）
- 工单已解决通知（标题/解决内容/解决时间/客服姓名）
- 新回复提醒通知（标题/回复内容/回复时间/客服姓名）

**实时 JSON 校验 + 卡片预览**：编辑模板字段值时实时校验 JSON 格式正确性，支持 `color` 字段着色预览（标题/关键字按微信规范 `#RRGGBB` 渲染），左侧表单 + 右侧预览卡片同步更新。

**发送历史记录**：记录最近 10 条发送历史，包含成功/失败状态、发送时间、目标客户、模板名称，支持点击历史项快速重发。

使用流程：
1. 进入「微信 → 通知消息」Tab，选择模式（模板消息 / 订阅通知）
2. 在会话搜索框输入客户关键词，下拉选中目标会话
3. 选择模板（或点击「常用模板」一键填充）
4. 填写模板字段值，左侧表单实时生成 JSON，右侧卡片预览渲染效果
5. 确认无误后点击「立即发送」

> 📌 通知消息需严格符合微信审核通过的模板格式；模板 ID 由微信公众平台分配，不可自定义。详细限制见微信公众平台模板消息运营规则与订阅通知运营规范。

#### 11.6.6 自定义菜单

管理微信公众号底部自定义菜单，支持可视化编辑与 JSON 双向同步，实时预览手机端效果。

**两种编辑模式**：页面右上角切换按钮在「可视化编辑」与「JSON 编辑」之间切换，双向同步菜单结构。
- **可视化编辑**（推荐日常维护）：表单式增删改菜单按钮，无需手写 JSON
- **JSON 编辑**（适合批量导入/导出）：直接编辑微信菜单 JSON 结构，支持「格式化」「清空」「加载默认示例」

**菜单结构规范**（与微信官方一致）：
- 一级菜单最多 3 个，名称 ≤ 16 字节（中文 ≤ 8 个字）
- 二级菜单最多 5 个，名称 ≤ 40 字节（中文 ≤ 20 个字）

**菜单类型与必填字段**：

| 类型 | 说明 | 必填字段 |
|------|------|----------|
| `click` | 点击推事件 | `key`（事件 KEY） |
| `view` | 跳转 URL | `url`（跳转链接，需 https） |
| `scancode_push` | 扫码推事件 | `key` |
| `scancode_waitmsg` | 扫码带提示 | `key` |
| `pic_sysphoto` | 系统拍照发图 | `key` |
| `pic_photo_or_album` | 拍照或相册发图 | `key` |
| `pic_weixin` | 微信相册发图 | `key` |
| `location_select` | 发送位置 | `key` |
| `media_id` | 下发图片 | `media_id` |
| `article_id` | 发布文章 | `article_id` |
| `miniprogram` | 小程序 | `appid` / `pagepath` / `url` |

**Schema 校验**：编辑过程中按菜单 `type` 实时校验必填字段，缺字段时输入框下方红色提示，发布前再次全量校验，确保提交的 JSON 符合微信规范。

**手机预览**：右侧模拟微信底部菜单栏渲染效果，hover 一级菜单展开二级菜单，直观查看最终在微信客户端的展示样式。

**菜单结构详情列表**：以表格形式列出所有菜单项的名称/类型/关键字/URL，带类型图标，便于快速浏览整体结构。

**线上菜单操作**：
- **拉取线上菜单**：调用 `cgi-bin/getcurrentmenu` 拉取当前线上菜单 JSON，显示在详情列表中
- **加载到编辑器**：将拉取到的线上菜单一键加载到可视化编辑器修改，避免从零重建
- **发布到线上**：校验通过后调用 `cgi-bin/menu/create` 发布菜单，立即生效（关注者需重新关注或取消关注再关注才能看到新菜单）
- **删除线上菜单**：调用 `cgi-bin/menu/delete` 清空线上菜单

使用流程：
1. 进入「微信 → 自定义菜单」Tab
2. 切换到「可视化编辑」模式
3. 点击「+ 添加一级菜单」，填写菜单名称、选择类型、填写必填字段
4. 如需二级菜单，点击一级菜单右侧「+」添加
5. 右侧手机预览实时查看效果
6. 完成后点击「发布到线上」，校验通过后菜单立即生效

> 💡 已关注公众号的用户需重新关注或取消关注再关注才能看到新发布的菜单；未关注用户扫码关注后即可看到最新菜单。

#### 11.6.7 会话视觉区分

为便于客服快速识别来源，所有微信相关元素使用统一的绿色调视觉标识：

- 会话列表中，微信来源客户显示绿色 MessageCircle 图标 + 「微信」徽章
- 客户气泡头像：亮绿 → 翠绿渐变（`from-green-500 to-emerald-600`）
- 客服气泡头像：深青 → 青蓝渐变（`from-teal-600 to-cyan-700`）
- 客户气泡左侧：绿色边栏
- 侧边栏客户标签：绿色徽章

### 11.7 钉钉聊天

钉钉聊天模块通过钉钉开放平台（Stream 模式或 Webhook 回调）将企业内部/外部联系人的钉钉消息接入 NoneadCSS，客服可在统一工作台回复钉钉消息。支持双向消息同步：文本、表情、图片、语音、视频、文件全类型接收与发送；客服回复支持多附件，图片在钉钉窗口内正常渲染预览，文件以卡片形式下载。

#### 11.7.1 前置准备（管理员）

1. 进入钉钉开放平台（https://open.dingtalk.com），创建**企业内部应用**或**第三方企业应用**
2. 获取应用凭证：`AppKey`、`AppSecret`、`AgentId`、`RobotCode`（RobotCode 为空可与 AppKey 共用）
3. 在「开发配置 → 事件订阅」中选择：
   - **Stream 长连接模式（推荐）**：无需公网回调 IP，适合内网部署，直接点已完成接入即可
   - **HTTP 回调模式**：需要公网可访问的回调 URL、`CallbackToken`、`EncodingAESKey`，填入系统后点「回调验证」
4. 订阅消息事件：`im.message.receive_v1`、`contact.user.modified`
5. 申请消息权限：`im.message:send`、`contact.user:read`、`robot:messageFile`（图片/文件上传下载）

> 💡 提示：如你的服务器**没有 IPv6 出口**，在钉钉开放平台控制台侧会提示连接 api.dingtalk.com 超时，NoneadCSS 已在代码层自动降级为 IPv4 连接，无需额外网络配置。

#### 11.7.2 系统配置

1. 管理员进入「功能模块 → 钉钉 → 配置」Tab
2. 选择**接入模式卡片**（顶部切换）：
   - **Stream 模式（推荐）**：只需要填 AppKey / AppSecret / AgentId / RobotCode
   - **HTTP 回调模式**：除上面基础字段外还需要填 CallbackToken / EncodingAESKey
   - 切换后字段会自动联动显隐，Stream 模式下不会显示 Token/Key
3. 填写：
   - **AppKey / AppSecret**：钉钉开放平台应用凭证（AES-GCM 加密存储，右侧显示「🔒 已配置」徽章）
   - **AgentId**：应用 AgentId
   - **RobotCode**：机器人编码，可空（留空时内部回退到 AppKey）
   - **接入模式**：刚才选择的卡片对应模式
   - **CallbackToken / EncodingAESKey**：仅 HTTP 模式可见
   - **关联邮箱 ID**：钉钉会话归属的邮箱
   - **启用自动欢迎语**：新客户首次发消息时自动回复（可选）
   - **启用钉钉接入**：总开关
4. 点击「保存配置」→ 「启动钉钉接入」按钮会自动保持开启状态 → 切换到「状态」Tab 验证连通性
   - Stream 连接状态：🟢 已连接 / 🟡 重连中 / 🔴 失败
   - API 可达性：3 秒超时探测，不会阻塞整个状态面板

#### 11.7.3 客服使用流程

1. 钉钉客户给应用发消息后，系统在「服务台 → 会话管理」自动创建**蓝色钉钉图标**来源的会话
2. 客服进入会话详情页，顶部显示蓝色「钉钉」徽章 + 客户昵称 + 所属企业信息
3. 回复支持的内容：
   - **文本 + 表情**：直接输入文字，点击表情按钮选择 24 个常用表情；钉钉侧的 `[流泪]` 等中文表情名在系统内会自动转换为对应的 emoji 显示
   - **图片 / 文件附件**：拖拽或点击附件按钮上传，支持多张图片；发送后：
     - 会话记录内：左侧气泡显示图片缩略图（点击可放大预览），右侧显示附件数量 × N
     - 钉钉窗口内：图片直接渲染为图片消息（sampleImageMsg），pdf/xlsx/docx 等文件显示为文件卡片（sampleFile），可在钉钉内直接下载/打开
   - **头像与昵称**：钉钉窗口显示的客服头像是系统用户资料里的头像和真实姓名（如 Tony Ke），不是机器人编码
4. 支持会话线程展开查看：左侧边栏显示「附件 × N」，点击任意附件可直接下载原文件

> ✅ 提示：从钉钉侧发过来的图片、语音、视频、文件，系统会自动下载并保存到对应会话的附件中（即使只发了一张图片），客服侧会话记录能直接预览。

#### 11.7.4 注意事项

- **Stream 模式**：无需暴露公网 IP，适合内网部署；应用启动时自动建连、注册连接凭证、心跳保活（30s 一次），断线自动指数退避重连（1s→2s→4s→8s→16s→60s）
- **Webhook 模式**：需要公网可访问的回调 URL + 签名校验（`sign` 字段与时间戳）；加解密模式与 CallbackToken/EncodingAESKey 三者必须一致
- 单聊消息**无 48h 窗口限制**，但营销类消息仍需遵守钉钉运营规范
- **消息与表情**：钉钉侧表情发送用 `[流泪]` 这种中文方括号名称，系统已内置 200+ 映射，客服侧直接显示对应 emoji；反向发送时表情以 Unicode 原样发到钉钉
- **消息撤回**：钉钉端撤回后系统自动标记对应线程为「已撤回」
- **多轮问答**（v2.2.12 修复）：客户在会话中连续发送多条消息时全部正常显示；历史版本曾因线程 MessageId 唯一约束冲突导致客户二次发送的信息未显示（T000113），现已修复（真实 Message-Id + 完整头信息存储）
- **附件发送**（v2.2.12 修复）：钉钉/飞书/微信/WhatsApp 渠道附件统一按系统内容根目录解析路径，修复历史版本因运行目录（CWD）与内容根目录不一致导致客户收不到图片的问题（T000112）
- 发附件失败常见排查：
  1. 上传文件大小是否超 25MB 上限
  2. 钉钉后台是否申请了 `robot:messageFile` 权限
  3. 系统状态 Tab 中 API 可达性显示为「🟢 可达」（如果是 IPv4 降级模式也完全可用）

### 11.8 飞书聊天

飞书聊天模块通过飞书开放平台事件订阅将飞书单聊/群聊消息接入 NoneadCSS，支持双向实时同步与富文本卡片消息。支持两种消息接收模式：**HTTP 回调模式**（需公网 IP/域名）和 **Stream 长连接模式**（推荐，无需公网 IP/域名，基于 WebSocket 自动接收事件）。

#### 11.8.1 前置准备（管理员）

1. 进入飞书开放平台（https://open.feishu.cn），创建**企业自建应用**
2. 获取应用凭证：`App ID`、`App Secret`
3. 开通权限：
   - 消息与群组：`im:message`、`im:message:send_as_bot`、`im:chat`、`im:resource:upload`（发送图片/文件必需，缺少会导致 `errcode=99991672` 错误）
   - 通讯录：`contact:user.base:readonly`
   - 事件订阅：`im.message.receive_v1`（消息接收）、`contact.user.updated_v3`（用户变更）
4. **接收模式选择**：
   - **HTTP 回调模式**：在飞书开放平台「事件订阅」中配置请求地址（Verification Token 与 Encrypt Key 与系统设置一致）
   - **Stream 长连接模式**：在飞书开放平台「事件订阅」中将接收方式切换为「长连接」，无需配置请求地址
5. 启用机器人能力，发布应用新版本

#### 11.8.2 系统配置

1. 管理员进入「功能模块 → 飞书聊天」
2. 页面采用 3-Tab 架构：**快速接入** / **高级设置** / **使用指南**

##### 快速接入 Tab

1. **接收模式选择**：两张卡片切换
   - **Stream 模式（WebSocket 长连接，推荐）**：无需公网 IP/域名，适合开发/测试/内网环境
   - **HTTP 回调模式**：需公网 IP/域名，适合生产环境
2. **启用飞书接入开关**：飞书品牌蓝 `#3370FF` 总开关，打开后按配置接入，关闭后停止任何接入
3. **条件参数表单**（按模式显示不同字段）：
   - Stream 模式：App ID、App Secret
   - HTTP 模式：App ID、App Secret、Verification Token、Encrypt Key
4. **连接状态卡片**：三态显示（未配置 / 已连接 / 连接异常），玻璃拟态设计
5. **动态配置指南**：根据所选模式显示对应的飞书开放平台配置步骤

##### 高级设置 Tab

填写：
- **App ID / App Secret**：飞书开放平台凭证（加密存储）
- **Verification Token**：事件订阅校验 Token（HTTP 模式必填，Stream 模式可空）
- **Encrypt Key**：事件内容 AES 加密密钥（可选，若飞书开启加密必填）
- **关联邮箱 ID**：飞书会话归属的邮箱
- **自动回复消息**：新会话欢迎语（可选）

##### 使用指南 Tab

飞书开放平台配置步骤、权限清单、常见问题解答。

3. 保存配置后，Stream 模式会自动建立 WebSocket 长连接（无需手动操作）
4. 切换到「状态」Tab，检查 `tenant_access_token` 获取、事件订阅、消息发送三项连通性

#### 11.8.3 客服使用流程

1. 飞书用户给应用机器人发消息 → 系统自动创建**飞书来源**会话
2. 客服接待：与其他渠道一致的统一回复体验
3. 支持发送：文本、富文本（Post）、图片、文件、交互卡片
4. 客服回复图片时，系统通过 base64+md5 方式发送；若飞书应用缺少 `im:resource:upload` 权限导致上传失败，系统会回退发送文本提示消息告知用户
5. 群聊：通过 @机器人 触发；机器人回复在群内 @对应发言人

#### 11.8.4 注意事项

- **Stream 长连接模式**：30s 心跳保活，断线指数退避重连（1s/2s/4s/8s/16s，封顶 60s），首次重连随机抖动避免雪崩
- **`tenant_access_token` 有效期 2 小时**，系统自动缓存与刷新，避免重复请求
- **飞书卡片回调**（按钮点击）通过配置的请求地址回传，系统自动将点击内容追加到会话线程
- **飞书图片/文件 URL** 需携带 `tenant_access_token` 下载，系统统一封装，客服无需关心
- **配置缓存**：启用飞书接入后，因三层缓存（后端 OutputCache / IMemoryCache / 前端 ModuleContext）可能最多 5 分钟才生效
- **启用开关自动关闭问题**：已修复，缓存过期后会从数据库重新加载配置，不再回退到 baseline
- **权限要求**：发送图片/文件必须开通 `im:resource:upload` 权限，否则图片上传失败

### 11.10 Facebook Messenger

Messenger 模块基于 Meta Graph API 将公共主页（Page）私信接入 NoneadCSS，客服可在系统中回复 Messenger 客户消息，入站事件经 Webhook 推送、出站消息经 Graph API 发送，历史记录统一留存在会话中。

#### 11.10.1 前置准备

- 在 Meta for Developers（https://developers.facebook.com）创建应用，并添加 Messenger 产品
- 绑定公共主页，取得 Page ID 与 Page Access Token（两者必须来自同一主页；Page Token 不是 App Token）
- 在应用「设置 → 基本」中取得 App Secret
- 自定义一串 Verify Token（随机字符串，需与 Meta 平台的 Webhook 设置一致）
- 准备公网 HTTPS 回调地址（TLS 1.2+，443 端口），本地开发需内网穿透

#### 11.10.2 系统配置

- 进入「功能模块 → Messenger」，默认打开「配置」Tab
- 基本信息：
  - Page ID：公共主页数字 ID，Webhook 回调里的 entry.id 与出站收件人校验都依赖它
  - 主页用户名：可选，仅用于坐席界面展示 m.me 链接
  - Graph API 版本：默认 v25.0（Meta 没有 v2x 别名，升级只需改这一项）
  - 关联邮箱：Messenger 会话归属的邮箱
- 凭据：
  - Page Access Token：公共主页访问令牌（加密存储，保存后不回显）
  - App Secret：用于校验 X-Hub-Signature-256（HMAC-SHA256 原始请求体）
  - Verify Token：GET 校验时与 hub.verify_token 逐字符比对（区分大小写）
- 行为：
  - 新会话自动回复：仅对新会话的第一条入站消息触发
  - 联系方式收集：从文本中提取姓名/手机/邮箱，缺字段时对新会话发一次引导语
  - 收到消息即标记已读（sender_action: mark_seen）
  - 发送前显示「正在输入」（sender_action: typing_on）
  - message_tag 策略：自动（窗口外带 HUMAN_AGENT）/ 始终带标签 / 不带标签（窗口外禁发）
- 运行参数：出站分段长度（单条文本超过该长度自动分段，Graph 单条上限 2000 字符）、回复窗口小时数（默认 24）
- 点击「保存配置」，再点「测试连接」（按已配置的 Graph API 版本调用 GET /me）

#### 11.10.3 Webhook 与订阅

- 回调地址：`https://<公网域名>/api/messenger`（必须是公网 HTTPS，否则 Meta 无法订阅）
- 在 Meta 应用的 Messenger → Webhook 中填入回调地址与 Verify Token；系统对 GET 校验请求原样返回 hub.challenge 纯文本（不是 JSON）
- POST 请求必须带 X-Hub-Signature-256，验签基于原始请求体字节；失败返回 401 且不落库
- 切换到「订阅」Tab，点击「提交订阅」（按已配置版本调用 POST /me/subscribed_apps），默认字段：messages / messaging_postbacks / messaging_optins / messaging_handovers / message_deliveries / message_reads；需要 pages_manage_metadata 权限
- 订阅成功后到 Meta 的 Webhook 面板确认已勾选对应字段
- Page 处于开发模式时只向测试账号推送事件，需把 Page 上线

#### 11.10.4 状态检查

- 切换到「状态」Tab：
  - 配置完整性：Page ID / Page Token / App Secret / Verify Token 四项是否齐备
  - 模块开关：已启用 / 未启用
  - Graph 可达性：正常 / 不可达（按已配置版本调用 GET /me）
  - Page Access Token：未检测到失效 / 已失效（附最近失效时间）
  - 最近一次 Graph 错误
  - 回调地址与 API 版本
- 24 小时回复窗口卡片：窗口内（剩余 X 小时）/ 即将到期 / 已过期 / 无会话

#### 11.10.5 会话回复与窗口

- 在「服务台 → 会话管理」中，来源标记为 Messenger 的会话自动识别
- 窗口内可自由发送文本、图片与文件；入站媒体按 25 MB 上限下载并转存为附件，出站走 Attachment Upload API
- 窗口外回复必须带 message_tag（默认 HUMAN_AGENT）；策略设为「不带标签」时窗口外会被拒绝发送
- 客户身份是 PSID，只在同一个 Page 内唯一且稳定，不是 Facebook 用户 ID，不能跨 Page 关联

#### 11.10.6 注意事项

- Page Access Token 由长期用户令牌派生约 60 天，由商业资产 / System User 授予的可长期有效；Messenger 没有刷新接口，失效后需重新换发并粘贴到设置页
- 窗口外发送失败常见 Graph 错误 68 / 2635，通常即窗口或 message_tag 问题
- App Secret 未配置、被加密密钥变更破坏，或网关重排了 JSON，都会导致验签失败（401）
- Graph 单条文本上限 2000 字符，超长会自动分段

### 11.11 Telegram

Telegram 模块通过 Bot API 接入机器人，入站支持 Webhook 推送与长轮询两种互斥方式，出站消息受 Telegram 频率限制约束。

#### 11.11.1 前置准备

- 在 Telegram 中找 @BotFather，执行 `/newbot` 创建机器人并取得 Bot Token
- 选择入站方式：Webhook 需要公网 HTTPS（Telegram 只接受 443 端口）；长轮询无需公网地址
- 如需在群里使用，提前确认群隐私模式（BotFather 的 `/setprivacy`）

#### 11.11.2 系统配置

- 进入「功能模块 → Telegram」
- 凭据：Bot Token（由 @BotFather 签发，加密存库、不再回显；粘贴新 Token 才会替换）
- 入站方式（二选一）：
  - Webhook 推送：Telegram 有新更新时立即推送到公网 HTTPS 回调地址
  - 长轮询：系统持续挂起 getUpdates 取更新，按 update id 断点续传，NAT 后也能工作
  - 两种方式互斥；getUpdates 返回 409 说明 Webhook 仍在生效；切换到轮询时可自动删除 Webhook
- 运行参数：
  - 自建 Bot API 服务与 Bot API 基础地址（默认 https://api.telegram.org，自建一般是 8081 端口）
  - Webhook 密钥：Telegram 不对请求体签名，这个密钥是唯一能证明更新来自 Telegram 的依据（留空自动生成）
  - Webhook 最大并发连接数（默认 40）
  - 长轮询超时（默认 25 秒）、单次取回条数（默认 100）
  - 单条消息最大字符数（默认 4096）
  - 全局发送速率（默认 25 条/秒）、单会话发送速率（默认 1 条/秒）
  - 会话匹配时间窗（默认 720 小时）
  - 接收群消息（默认关闭）
- 保存后点「连通性测试（getMe）」确认机器人身份

#### 11.11.3 Webhook 注册与长轮询

- Webhook 模式：填写回调地址（`https://<公网域名>/api/telegram/webhook`），点「注册 Webhook」写入 Telegram 侧；不再使用时点「删除 Webhook」
- 长轮询模式：系统自动启动轮询，状态页显示 offset 游标与「长轮询运行中」
- 从 Webhook 切到轮询前先删除 Webhook，否则 getUpdates 会返回 409

#### 11.11.4 状态检查

- 切换到「状态」Tab：
  - 机器人身份：用户名、Bot Token 是否已配置
  - Cloud API 可达性
  - 入站投递：入站模式、Webhook 已注册地址、Telegram 侧待投递更新数、轮询 offset 游标
  - 群隐私模式：已开启（只能看到 /命令、回复与 @ 提及）/ 已关闭（能看到群里所有消息）
  - 已标记为不可投递的会话数
  - 最近一次 Webhook 错误

#### 11.11.5 会话回复

- 机器人永远不能主动开启会话：用户未先给机器人发过消息时，发送会以 403 失败
- 超长文本按单条消息最大字符数（默认 4096）分段
- 群聊需开启「接收群消息」；群隐私模式开启时，机器人只能看到命令、回复与 @ 提及
- 同一客户在会话匹配时间窗内复用已有会话，而不是新建

#### 11.11.6 注意事项

- 频率限制：单机器人约 25 条/秒，单会话 1 条/秒，群内 20 条/分钟
- Webhook 与长轮询不能同时启用，切换顺序见 11.11.3
- Webhook 回调只接受 HTTPS 443 端口

### 11.12 LINE

LINE 模块通过 LINE Messaging API 接入官方账号，支持 reply（免费）与 push（消耗配额）两种出站方式，Webhook 使用 X-Line-Signature 验签。

#### 11.12.1 前置准备

- 在 LINE Developers 创建 Provider 与 Messaging API 频道
- 取得 Channel ID 与 Channel secret
- 在「Messaging API」页签发长期 Channel access token（长期令牌），并记录 Key ID
- 准备公网 HTTPS 地址；在 LINE 控制台「Webhook settings」把回调地址设为 `https://<公网域名>/api/line/webhook` 并打开 Use webhook

#### 11.12.2 系统配置

- 进入「功能模块 → LINE」
- 频道凭据：
  - Channel ID：显示在客户的加好友链接里
  - Channel secret：只用于校验 X-Line-Signature 与签发附件直链，不会回显
  - Channel access token：长期令牌，等同凭据，只写入本机密文
  - 令牌 Key ID：令牌被吊销后轮换——先撤销旧 Key，再粘贴新令牌
- Webhook：
  - 启用 Webhook 入站
  - 显示回调地址，可「写入 LINE 端点」（需令牌具备 Channel management 权限）
  - 「校验回调」触发 LINE 侧的 webhook test；LINE 不使用 GET hub.challenge 握手
  - 本系统回调地址与 LINE 登记端点不一致时，页面会提示重新写入
- 运行参数：
  - 自动标记已读（markAsReadToken）、发送前显示「加载中…」（仅 reply 场景）
  - 补全客户资料（调 LINE Profile API 取昵称/头像，不占消息配额）
  - 单条文本上限（默认 5000 字符）、单次请求最多消息数（1–5）
  - replyToken 有效秒数（默认 25）、发送重试次数（0–5，默认 0）
  - 配额告警阈值（默认 80%）、人工接管静默分钟数（默认 60，0 表示关闭）
- 附件直链：
  - 对外根地址（留空取 App:BaseUrl）、直链有效分钟数（默认 7 天）
  - 入站附件上限（默认 100 MB）、出站附件上限（默认 10 MB）
  - 出站图片扩展名（默认 jpg,jpeg,png，保存时统一小写去重）
- 保存配置

#### 11.12.3 状态检查

- 凭据是否已配置、API 是否可达
- 令牌到期时间，或显示「长期令牌（不过期）」
- LINE 侧回调是否与系统一致
- 当前回复方式：reply（免费、25 秒窗口内）/ push（消耗月度配额）/ 未知（尚无出站记录）
- 月度 push 配额与使用百分比（超过告警阈值显示告警徽标）

#### 11.12.4 会话回复与配额

- 客户来消息后 25 秒内优先使用 reply，不占配额；超时或主动外发改走 push，消耗月度配额
- 自动回复只对新会话首条客户消息生效，走 replyToken，不占配额
- LINE 没有聊天媒体上传接口，出站图片/文件必须来自本系统公网 HTTPS 直链（不可重定向、不可要求登录），因此需正确配置附件对外根地址
- 坐席回复后写入接管备注，静默分钟数内机器人不再自动回复

#### 11.12.5 注意事项

- 只有 push 计费，reply 免费但必须在约 25 秒内使用
- replyToken 一次性，过期后只能改走 push
- 429 / 500 / 503 等可重试错误按配置重试；重复投递风险由后端守卫兜住
- 附件直链依赖公网可达，内网部署需额外配置对外地址

### 11.13 Apple 信息（iMessage）

iMessage 是 Apple 的商标，面向客户统一称「Apple 信息」。系统支持三种接入方式：自建桥接服务（推荐）、经 Apple 核准的 MSP 连接器（AMB）、直连 Apple 网关（实验性）。

#### 11.13.1 前置准备

- 自建桥接服务：准备一台专用 Mac 常驻，登录独立 Apple ID、开启完全磁盘访问、禁止休眠，并部署 BlueBubbles 兼容桥接服务
- MSP 连接器：需要 Apple 核准的商务信息连接器，以及 Apple 签发的 MSP 协议资质
- 直连 Apple 网关：需自行取得 Apple 授权，属于实验功能，不在 Apple 公开条款覆盖范围内
- 准备桥接服务可访问的公网 HTTPS 基础地址，用于入站回调

#### 11.13.2 系统配置

- 进入「功能模块 → iMessage」→「接入配置」Tab
- 接入方式：自建桥接服务 / 经 MSP 连接器接入 Apple 商务信息 / 直连 Apple 网关
- 桥接服务连接：
  - 桥接服务地址（BlueBubbles 兼容服务的 HTTP(S) 地址，需含端口）、桥接服务密码
  - 校验桥接服务 TLS 证书（仅本机自签名证书时关闭）
  - 桥接服务最低版本（默认 1.0.0，低于该版本拒绝接入）
  - 入站共享密钥：桥接调用 Webhook 时需带 X-Webhook-Secret 头（或 ?secret=），留空则仅靠路径不可猜保护
  - 公网回调基础地址、Webhook 路径（固定为 `/api/imessage/bluebubbles/webhook`，改成别的值会被归一化并记告警）
  - 发送方式：AppleScript 桥接（稳定）/ 私有 API（更快，需关闭 SIP）
  - 鉴权方式：Bearer 令牌头 / 查询串凭据（旧版）
  - 启动时读取历史消息（使较早会话线程可见）
  - 发送速率上限（默认 20 条/分钟）、会话匹配时间窗（默认 168 小时）
  - 允许降级为 SMS（默认关闭，静默降级会让客户困惑）、入站白名单（handle/邮箱/群组，逗号分隔）
- MSP 连接器：
  - MSP 标识、连接器、MSP 共享密钥（用于 HS256 签发令牌，保存后不回显）
  - 商家标识（urn:biz:…）、令牌有效期（Apple 上限 3600 秒，超出会被截断）
  - Apple 网关地址（默认 https://mspgw.push.apple.com）、降级渠道（Apple 强制要求配置，通常为短信）
- 保存配置

#### 11.13.3 Webhook 注册与连接测试

- 点「在桥接服务上注册 Webhook」；桥接服务只会向已注册地址推送事件
- 连接测试可填写测试接收方（已在该桥接上的 handle）；仅做健康检查时留空
- 状态页显示已注册的 Webhook 地址

#### 11.13.4 状态检查

- 切换到「运行状态」Tab：
  - 连接状态、桥接服务版本
  - 最近一次入站消息时间
  - Webhook 注册结果与已注册地址
- AMB 模式下的连通性测试只能确认网关可达，不能证明消息真的能送达

#### 11.13.5 会话回复与限制

- iMessage 没有 24 小时窗口概念：投递跟随会话状态，已结束的会话绝不能主动外发
- Apple 商务邀请必须使用 Apple 编写的模板，并配置短信兜底渠道
- AMB 附件使用 AES/CTR 密钥协商，本系统尚未实现，因此附件只能接收、无法解密
- 频率过高会被 Apple 与桥接服务静默丢弃，需按较低速率配置

#### 11.13.6 注意事项

- 自建桥接属社区软件，未获 Apple 认可，使用它可能不符合 Apple 条款，并可能随 macOS 更新而失效
- 直连 Apple 网关为实验功能，随时可能失效
- 未经认可的接入方式可能导致 Apple ID 或商务账号被封
- 桥接 Mac 不能休眠，且应使用单独的 Apple ID

## 12. 集成与扩展

### 12.2 API 密钥

API 密钥用于第三方系统通过 REST API 访问系统数据。

#### 创建 API 密钥

1. 进入「集成与扩展 → API 密钥」
2. 点击「+ 创建密钥」
3. 填写名称
4. 选择权限范围（Scope）：
   - `conversations:read` - 读取会话
   - `conversations:write` - 写入/修改会话
   - `customers:read` - 读取客户
   - `customers:write` - 写入/修改客户
   - `tickets:read` - 读取工单
   - `tickets:write` - 写入/修改工单
5. 保存后系统生成密钥（仅显示一次，请妥善保存）

> ⚠️ API 密钥等同于账户凭证，请勿泄露。可在列表中随时禁用或删除密钥。

#### 权限范围（Scope）说明

系统采用最小权限原则，建议为每个 API 密钥仅分配必要的权限：

| 权限范围 | 说明 | 适用场景 |
|----------|------|----------|
| `conversations:read` | 只读会话数据 | 报表系统、数据同步 |
| `conversations:write` | 创建、修改、删除会话 | 工单系统集成 |
| `customers:read` | 只读客户数据 | CRM 同步、客户画像 |
| `customers:write` | 创建、修改客户 | 客户注册系统 |
| `tickets:read` | 只读工单 | 监控告警 |
| `tickets:write` | 创建、修改工单 | 外部系统创建工单 |

> 🔒 **安全建议**：
> - 为不同用途创建独立的 API 密钥
> - 仅分配必要的最小权限
> - 定期轮换密钥，禁用不再使用的密钥
> - 密钥不要硬编码在代码中，使用环境变量或密钥管理系统

### 12.3 自定义字段

自定义字段允许扩展会话、客户等实体的属性：

| 标签页 | 说明 |
|--------|------|
| 全部 | 显示所有可见报表（含他人创建的共享报表） |
| 我的置顶 | 显示当前用户置顶的报表，便于快速访问 |
| 垃圾箱 | 显示已软删除的报表，标签右上角带数量角标，标识当前垃圾箱中的报表总数 |

#### 报表删除与垃圾箱

删除报表采用软删除机制，报表不会直接物理删除，而是移入垃圾箱，可在垃圾箱中恢复。

**删除报表（移入垃圾箱）**：

1. 在「全部」或「我的置顶」标签页中，找到要删除的报表卡片
2. 点击卡片右上角的「⋯」按钮，或在卡片上右键，打开操作菜单
3. 选择「删除」
4. 系统弹出确认框，提示「删除后报表将移入垃圾箱，你可以在垃圾箱中恢复」
5. 点击「确定」，报表被移入垃圾箱，列表中不再显示

> 💡 删除操作仅执行软删除，报表数据仍保留在垃圾箱中，可随时恢复。

**查看垃圾箱**：

- 点击报表列表顶部的「垃圾箱」标签页进入
- 标签右侧的数量角标显示当前垃圾箱中的报表总数
- 垃圾箱中以卡片形式展示已删除报表，支持按名称搜索

**恢复报表**：

在垃圾箱标签页中，可通过以下两种方式恢复报表：

- **卡片按钮**：点击报表卡片底部的「恢复」按钮（绿色）
- **右键菜单**：在卡片右上角右键，选择「恢复报表」

恢复操作会弹出二级确认框，确认后报表将重新回到「全部」列表中。

**永久删除报表**：

在垃圾箱标签页中，可通过以下两种方式永久删除报表：

- **卡片按钮**：点击报表卡片底部的「永久删除」按钮（红色）
- **右键菜单**：在卡片右上角右键，选择「永久删除」

永久删除操作会弹出二级确认框，并显示额外的琥珀色警告提示，确认后报表将被物理删除，不可恢复。

> ⚠️ 永久删除操作不可恢复，报表及其配置将被彻底清除，请谨慎操作。

**清空垃圾箱**：

- 点击垃圾箱标签页顶部的「清空垃圾箱」按钮
- 仅当垃圾箱中存在已删除报表时按钮才可用，无记录时按钮置灰
- 操作会弹出二级确认框，并显示额外的琥珀色警告提示
- 确认后批量物理删除垃圾箱中的所有报表，不可恢复

> ⚠️ 清空垃圾箱操作不可恢复，将永久删除所有已软删除的报表，请谨慎操作。

#### 权限说明

| 操作 | 普通用户 | 超级管理员 |
|------|---------|-----------|
| 删除报表（移入垃圾箱） | ✅ 仅自己创建的报表 | ✅ 所有报表 |
| 查看垃圾箱 | ✅ 仅自己创建的报表 | ✅ 所有报表 |
| 恢复报表 | ✅ 仅自己创建的报表 | ✅ 所有报表 |
| 永久删除报表 | ✅ 仅自己创建的报表 | ✅ 所有报表 |
| 清空垃圾箱 | ✅ 仅清空自己创建的报表 | ✅ 清空所有报表 |

> 💡 普通用户仅能操作自己创建的报表，超级管理员可管理系统中所有报表。

- **操作分布 Top 8**：按操作类型分组，显示出现频率最高的前 8 种操作及数量条形图。
- **实体占比**：按实体类型分组，显示各实体类型在审计日志中的占比。

> 💡 v2.2.10 起，操作分布与实体占比卡片已全面汉化：前端内置 50 个 Action 与 61 个实体类型的中文映射，并支持 `calendar.` / `time_entry.` 前缀兜底，未命中时自动回退显示原始值。中文界面不再出现英文原文（如 `calendar.update`、`WorkflowExecutionLog`、`SystemOption`）。

#### 14.1.4 CSV 导出

点击「导出 CSV」按钮可导出当前过滤条件下的审计日志：

- 服务端生成 UTF-8 BOM 编码的 CSV 文件，Excel 打开不会乱码。
- 文件名格式：`audit-logs_YYYYMMDD-HHmmss.csv`（如 `audit-logs_20260827-143205.csv`）。
- 最大导出 10000 行，防止内存溢出。
- 浏览器直接下载 Blob，无需中间页跳转。

#### 14.1.5 HMAC-SHA256 完整性校验

审计日志在写入时即生成 HMAC-SHA256 签名，用于检测后续是否被篡改。

> ⚠️ v2.2.10 修复：此前因写入时 `CreatedAt` 使用 UTC（Kind=Utc，带 `Z` 后缀）而 SQLite 读回后 Kind=Unspecified（不带 `Z` 后缀），导致签名载荷与校验载荷不一致、HMAC 校验恒失败。现已统一按 UTC 渲染时间戳，并对存量 56887 条日志完成一次性重签。若已升级，请先在「批量校验完整性」中确认当前页均显示绿色 ShieldCheck。

**批量校验**：

- 点击页面右上角「批量校验完整性」按钮，对当前页所有日志进行校验。
- 校验完成后，列表的「签名」列显示图标：
  - 🛡️ **绿色 ShieldCheck**：签名校验通过，记录未被篡改。
  - ⚠️ **红色 ShieldX**：签名校验失败，记录疑似被篡改。
- 篡改行会以浅红色底色高亮，便于快速定位。
- 校验结果会回写到列表项的 `isTampered` 字段，无需逐条打开详情。

**单条校验**：

- 在日志详情弹窗中点击「校验签名」按钮，可对单条日志进行校验。
- 返回结果包含：`isValid`（是否有效）、`storedSignature`（存储签名）、`expectedSignature`（期望签名）、`verifiedAt`（校验时间）。

## 16. 常见问题

### Q1：忘记密码怎么办？

在登录页点击「忘记密码？」，输入注册邮箱获取重置链接。若未配置邮件服务，请联系管理员在「用户管理」中重置。

### Q2：为什么收不到新邮件？

请检查：
1. 「邮件中心 → 邮箱管理」中邮箱状态是否正常
2. 点击「测试连接」验证 IMAP 配置
3. 确认 `appsettings.json` 中 `Email:FetchEnabled` 为 `true`
4. 查看后端日志是否有收取异常

### Q3：如何让会话自动分配？

在「自动化 → 工作流自动化」创建工作流：
- 触发器：会话创建
- 动作：分配给（指定客服或团队）

### Q4：深色模式切换后没有效果？

请确保在「个人中心 → 偏好设置」中切换深色模式开关。如果仅通过浏览器设置切换可能不会同步到系统。清除浏览器缓存后重试。

### Q5：如何导出会话数据？

进入「数据中心 → 数据导入导出」，选择「导出」，勾选会话，选择格式（JSON/CSV），点击导出。

### Q6：API 密钥丢失怎么办？

API 密钥仅在创建时显示一次。若丢失，请进入「集成与扩展 → API 密钥」禁用旧密钥并创建新密钥。

### Q7：如何启用功能模块？

管理员进入「集成与扩展 → 模块管理」，将对应模块（日历、知识库、在线聊天等）的状态切换为启用，保存后侧边栏「功能模块」菜单将显示对应入口。

### Q8：浏览器通知不弹出？

1. 确保在「个人中心 → 偏好设置」中开启了浏览器通知
2. 在浏览器地址栏左侧点击锁图标，允许该网站发送通知
3. 确认操作系统未开启「勿扰模式」
4. 不同浏览器（Chrome/Firefox/Edge/Safari）的通知权限设置位置略有不同

### Q9：SLA 超时了怎么办？

1. 在仪表盘查看超时会话列表
2. 优先处理即将超时或已超时的会话
3. 如需调整时限，进入「自动化 → SLA 策略」修改策略

### Q10：如何切换界面语言？

点击顶部导航栏右侧的语言选择器，切换简体中文 / English。也可在「个人中心 → 个人资料」中设置默认语言。

### Q11：上传的附件会被病毒扫描吗？

会。所有上传的附件和收到的邮件附件都会经过自动病毒扫描，包括恶意特征码检测、可执行文件拦截、可疑 MIME 类型检测和扩展名欺骗检测。未通过安全检查的文件会被拒绝。

### Q12：回复写了一半，如何保存草稿？

在会话详情页的回复输入框下方，点击「保存草稿」按钮即可保存。下次进入该会话时，草稿会自动回填。回复发送成功后，草稿会自动删除。

### Q13：删除客户会同时删除关联的会话吗？

是的。删除客户时，系统会自动级联软删除该客户名下的所有关联会话（包括已软删除的会话）。已删除的客户和会话均可在回收站中恢复。若遇到删除失败的情况，请联系管理员检查数据库状态。

### Q14：满意度评价是如何触发的？

当会话状态变更为"已关闭"时，系统会自动向客户发送满意度评价邀请邮件。客户提交评价后，系统会再自动发送一封感谢邮件。这些都是通过工作流自动化实现的，可在「自动化 → 工作流自动化」中配置。

### Q15：满意度评价是几星制？

系统采用 **5 星制** 满意度评价：

- ⭐⭐⭐⭐⭐ 5 星：非常满意
- ⭐⭐⭐⭐ 4 星：满意
- ⭐⭐⭐ 3 星：一般
- ⭐⭐ 2 星：不满意
- ⭐ 1 星：非常不满意

客户可在评价页面选择 1-5 星，并填写文字评论。评价结果会显示在会话详情页的「客户评价」区域。

### Q16：如何克隆一个会话？克隆后消息记录会保留吗？

进入会话详情页，点击页面顶部的「克隆」按钮即可创建该会话的副本。克隆后的会话会保留：
- 所有客户消息（含原始客户信息）
- 所有客服回复（回复人更新为当前操作用户）
- 所有内部备注和附件
- 标签、优先级等分类属性

克隆后的会话标题会自动添加「[副本]」标识，便于区分原始会话和副本。

### Q17：批量操作部分失败怎么办？会影响已经成功的吗？

批量操作采用事务保障，每个会话的操作是独立的。如果部分会话操作失败：
- **成功的会话**：操作已生效，不会回滚
- **失败的会话**：系统会显示具体的失败原因，便于排查
- **结果反馈**：操作完成后会显示成功数量、失败数量和错误详情

您可以根据错误提示修复问题后，对失败的会话重新执行操作。

### Q18：软删除和永久删除有什么区别？

| 删除类型 | 操作方式 | 可恢复性 | 说明 |

如果连续输入错误密码 5 次，账户会被临时锁定 15 分钟。您可以：

- 等待 15 分钟后自动解锁，再重新登录

### Q21：API 密钥的权限范围（Scope）是什么意思？

权限范围（Scope）控制 API 密钥可以访问哪些接口和数据。系统采用最小权限原则，每个密钥只应被授予必要的权限：

- `conversations:read` - 只能读取会话，不能修改
- `conversations:write` - 可以创建和修改会话
- `customers:read` - 只能读取客户数据
- `customers:write` - 可以创建和修改客户

建议为不同用途创建独立的 API 密钥，避免一个密钥拥有过多权限。

### Q22：系统的安全性如何保障？有哪些安全机制？

系统采用多层安全防护机制：

**身份认证与访问控制：**
- JWT + Refresh Token 双令牌机制，支持令牌轮换和异常检测
- 登录失败锁定（连续 5 次错误锁定 15 分钟）
- 密码强度校验（最小长度、复杂度、弱密码字典、常见模式检测）
- 角色基于访问控制（RBAC），支持邮箱级别隔离

**数据安全：**
- 所有敏感数据（密码、令牌、邮箱密码）加密存储
- 密码重置自动撤销所有未使用的重置链接和已登录设备
- 审计日志记录所有关键操作，支持追溯
- 客户头像 URL 协议白名单校验：仅允许 `https://`、本地相对路径（`/` 开头）和 `data:image/*` 内联图片，禁止 `http://`（明文传输）、`javascript:`、`vbscript:`、`file://`、`ftp://` 等危险协议，防止 XSS 注入

**附件安全：**
- 自动病毒扫描（恶意特征码、可执行文件、MIME 类型检测）
- 文件大小限制（25MB）和格式白名单
- 扩展名欺骗检测

**API 安全：**
- API 密钥最小权限原则（Scope 控制访问范围）
- HMAC 签名验证（Webhook）
- HTTPS 强制加密传输

> 💡 建议定期检查审计日志，及时发现异常操作；定期轮换 API 密钥，禁用不再使用的密钥。

### Q23：如何理解软删除机制？数据会被永久删除吗？

系统采用软删除机制保护数据安全：

**软删除特性：**
- **标记删除**：删除操作不会真正删除数据，而是在数据库中标记 `DeletedAt` 字段
- **可恢复性**：已删除的数据可在回收站中恢复，无需担心误删
- **级联删除**：删除客户时，会自动级联软删除其名下的所有关联会话
- **查询过滤**：所有查询自动过滤已删除数据，保证数据一致性

**永久删除：**
- 仅在「垃圾邮件」中手动执行「永久删除」时才会真正删除数据
- 永久删除操作不可逆，请谨慎操作
- 建议先在垃圾邮件中确认后再执行永久删除

**适用范围：**
软删除机制适用于：会话、客户、标签、邮件模板、用户、团队、角色等核心实体。

### Q25：系统有性能优化吗？查询速度快吗？

系统在数据库和代码层面进行了多维度优化：

**数据库优化：**
- **索引优化**：为高频查询字段添加索引（如会话线程的 MessageId、附件的 ThreadId、星标的复合索引）
- **复合索引**：NotificationRule 实体新增 4 个复合索引（EventType+IsActive+MailboxId+UserId+DeletedAt 等），覆盖通知规则匹配、按邮箱列表查询等核心路径，预计高频查询性能提升 60%+
- **AsNoTracking 只读优化**：全部 37 个仓储的只读查询方法（共 68+ 个）均已添加 `.AsNoTracking()`，跳过 ChangeTracker 实体追踪，显著降低在线客服高并发场景下的内存占用
- **批量操作优化**：`BulkUpdatePriorityAsync`、`BulkDeleteAsync` 从循环逐个 SaveChanges 改为 `ExecuteUpdateAsync` 单条批量 SQL，消除 N+1 事务问题
- **软删除过滤**：所有查询自动过滤已删除数据，使用索引提升查询效率
- **分页查询**：避免一次性加载大量数据，默认每页 10-20 条

**代码优化：**
- **异步处理**：使用 async/await 提升并发处理能力
- **缓存机制**：减少重复数据库查询（如邮件模板、用户信息）
- **IOptions 配置化**：将 45 处硬编码 TimeSpan 提取到 `ChatOptions`、`CacheOptions`、`OAuthOptions` 等独立配置节，支持环境变量覆盖，无需改代码即可调参

**扩展性设计：**
- 支持 SQLite（开发环境）和 SQL Server（生产环境）
- 后台任务使用 Quartz.NET 定时调度，避免阻塞主线程
- SignalR 实时通信，减少页面刷新

> 💡 如果遇到查询慢的情况，建议检查是否有大量历史数据未归档，或联系管理员优化数据库索引。

### Q37：日历事件编辑时提示「并发冲突」怎么办？

这是因为系统使用乐观锁（RowVersion）防止并发更新覆盖。当两人同时编辑同一事件时，后保存者会收到冲突提示。

**解决方法**：刷新页面获取最新数据后重新编辑保存。

### Q38：如何启动/停止生产环境服务？

生产环境部署在 `C:\noneadcss\Production` 目录，提供独立的 PowerShell 脚本：

```powershell
# 启动生产环境（后端 :5009 + Nginx :5173）
powershell.exe -ExecutionPolicy Bypass -File C:\noneadcss\Production\start-prod.ps1

# 停止生产环境
powershell.exe -ExecutionPolicy Bypass -File C:\noneadcss\Production\stop-prod.ps1
```

启动脚本会自动：检查并停止已运行的服务 → 启动后端并等待健康检查 → 启动 Nginx 并验证前端可访问。

## 附录 D. 最佳实践

### D.1 会话处理最佳实践

**响应时效：**
- 优先处理 SLA 即将超时的会话（仪表盘会高亮提醒）
- 建议设置首次响应时间 SLA（如 2 小时），提升客户满意度
- 使用宏命令快速执行标准流程（关闭工单 + 发送满意度邀请）

**会话管理：**
- 定期清理垃圾邮件，执行永久删除释放存储空间
- 使用标签分类会话（如「售前」「售后」「VIP」），便于筛选和统计
- 为重点会话添加关注者，确保团队协作顺畅

**草稿管理：**
- 回复内容较长时，建议定期点击「保存草稿」防止丢失
- 草稿按会话粒度保存，切换会话不会影响其他会话的草稿

### D.2 客户管理最佳实践

**数据维护：**
- 定期更新客户信息（公司、电话、地址），保持数据准确性
- 使用自定义字段记录业务特定信息（如 VIP 等级、行业分类）
- 定期导出客户数据备份，防止数据丢失

**批量操作：**
- 批量删除前先确认客户列表，避免误删
- 批量导出选择 CSV 格式（UTF-8 BOM 编码），Excel 直接打开不乱码

### D.3 自动化配置最佳实践

**工作流设计：**
- 避免创建过于复杂的工作流，建议拆分为多个简单工作流
- 定期检查工作流执行日志，及时发现异常
- 使用「执行宏」动作封装多步操作，便于维护和复用

**宏命令使用：**
- 为宏命令命名清晰（如「关闭并标记已解决」），便于团队成员理解
- 将常见流程（如满意度邀请、标签管理）保存为宏，避免重复操作

**SLA 配置：**
- 根据客户类型设置不同的 SLA 策略（如 VIP 客户响应时间更短）
- 定期查看 SLA 报表，分析超时原因并优化流程

### D.4 安全管理最佳实践

**账户安全：**
- 强制定期修改密码（建议 90 天），使用强密码策略
- 禁用长期未登录的账号，降低安全风险
- 为客服分配最小必要权限，避免权限过大

**API 密钥管理：**
- 为不同用途创建独立密钥，避免单一密钥权限过大
- 定期轮换 API 密钥（建议每季度）
- 密钥不要硬编码在代码中，使用环境变量或密钥管理系统

**审计日志：**
- 定期检查审计日志，关注异常操作（如批量删除、权限变更）
- 设置关键操作告警（如用户创建、角色变更）

### D.5 性能优化建议

**系统使用：**
- 避免同时打开过多会话详情页，减少浏览器内存占用
- 使用分页浏览会话列表，避免一次性加载大量数据
- 定期清理垃圾邮件和历史会话，保持数据库性能

**附件管理：**
- 压缩大文件后再上传，减少存储和传输压力
- 定期清理无用的邮件附件，释放存储空间

**通知设置：**
- 根据工作需要调整通知频率，避免通知过多干扰工作
- 使用浏览器通知而非邮件通知，减少邮件服务器压力

### D.6 在线聊天最佳实践

**接待效率：**
- 定期查看聊天概览页的「等待接待」列表，及时接入客户
- 使用快捷回复快速响应常见问题，提升首次响应速度
- 善用 @提及功能邀请同事协助处理复杂问题

**消息管理：**
- 发送错误的消息可在 2 分钟内撤回，避免误导客户
- 需要补充信息时使用编辑功能，避免连续发送多条消息
- 关注消息已读回执，了解客户是否已查看重要信息

**转工单时机：**
- 问题复杂需要长期跟进时，及时转工单
- 客户要求提供详细文档/附件时，转工单便于文件管理
- 需要跨部门协作时，转工单便于分配和追踪

### D.7 知识库管理最佳实践

**分类设计：**
- 分类层级建议不超过 3 级，便于快速定位
- 使用清晰的命名规范（如「产品 → 安装 → 常见问题」）
- 为不同邮箱团队创建专属分类，实现数据隔离
- 合理使用排序值控制分类显示顺序

**文章编写：**
- 标题简洁明了，包含关键词便于搜索
- 善用摘要字段概述文章内容，方便快速预览
- 使用 Markdown 格式化（标题、列表、代码块）提升可读性
- 添加标签便于分类和检索
- 定期更新已发布文章，保持内容时效性

**生命周期管理：**
- 草稿状态用于编辑中内容，确认无误后发布
- 过时内容归档而非删除，保留历史参考
- 定期清理垃圾箱，执行彻底删除释放存储

### D.8 日历管理最佳实践

**事件创建：**
- 为重要事件设置提前提醒（如 15 分钟、1 小时）
- 会议事件填写参会人和会议链接，便于准时参加
- 重复日程设置合理的结束日期或次数，避免无限展开

**团队协作：**
- 创建事件时指定负责人，明确责任
- 关联邮箱和会话，便于上下文追踪
- 使用日历订阅将日程同步到外部日历应用

**数据维护：**
- 定期清理已完成/已取消的事件
- 垃圾箱中的事件定期彻底删除或恢复
- 重复日程调整时注意选择正确的更新模式（仅本次/本次及后续/全部）

## B.1 自定义报表 · 垃圾箱

**进入方式**：侧边栏「报表」→「自定义报表」页面 → 顶部新增「垃圾箱」Tab，Tab 标题带实时数量角标。

**操作能力**：

| 按钮位置 | 按钮 | 说明 |
|---------|------|------|
| 垃圾箱 Tab 顶部 | 清空垃圾箱 | 一键清空当前用户可见的所有已删除报表（普通用户仅自己的，SuperAdmin 全量），触发二级确认防误操作 |
| 每条已删除报表行 | 恢复 | 将报表从垃圾箱还原到主列表，恢复后原创建者、权限、共享范围、调度配置**全部保留** |
| 每条已删除报表行 | 永久删除 | 从数据库物理删除（不可恢复）；**普通用户只能永久删除已处于垃圾箱中的自己报表**，SuperAdmin 可对任意状态任意报表永久删除 |

**权限矩阵**（与 v2.2.1 一致）：

| 操作 | 普通用户（自己创建的）| 普通用户（他人创建的）| SuperAdmin |
|------|---------------------|---------------------|------------|
| 查看垃圾箱列表 | ✅ 只看自己的 | ❌ 看不到 | ✅ 所有用户 |
| 恢复 | ✅ | ❌ → 403 | ✅ |
| 永久删除 | ✅（必须先软删除）| ❌ → 403 | ✅（任意状态）|
| 清空垃圾箱 | ✅ 仅自己的 | ✅ 仅自己的 | ✅ 全量 |

## B.2 人工客服 Widget 跨域嵌入

v2.2.1 起 `css.example.com:5173/chat/widget` 可嵌入 `http://www.example.com`（拓德首页）的右下角浮窗（以及白名单内的其他合作站点）。

**客服侧用法（不变）**：
- 会话进入后「会话详情」中客户来源为「**在线聊天**」（蓝灰色 Globe 图标）。
- 回复、附件、消息撤回/编辑/已读回执、@提及同事、转工单、快捷回复 — 与在线聊天页面完全一致。

**客户侧用法（不变）**：
- 右下角气泡 → 展开 360×560 浮窗 → 输入会话发起 → 系统分配客服 → 双方聊天 → 结束后 1-5 星评分。

**管理员注意**：如需将 Widget 嵌入新站点，需要运维在 `Production/nginx.conf` 的 `location /chat/widget` 中把新域名加到 `frame-ancestors` 白名单，然后 `nginx.exe -s reload`。

## B.3 客户管理 · 删除前置提示

v2.2.1 起在「客户管理」页点击「删除」后，会弹出**二级提示框**明确告知：

> 删除该客户后，其名下所有会话、附件、知识库点赞记录、标签关联将一并进入回收站（30 天后可永久删除）；**通道关联的 OpenID/UnionID/wa_id 等记录也会一并软删除**。是否继续？

点击「确认删除」才真正执行。避免原一次确认造成的误删。

## B.4 邮箱 / 渠道配置页的一个安全变化

v2.2.1 起，如果您使用的 `Encryption__Key` 与创建这些渠道/邮箱配置时的密钥不一致，页面上 `Password`、`AppSecret`、`OAuthAccessToken` 等敏感字段会显示为空（而不是把密文或乱码显示出来）。遇到该情况：
1. 查看生产服务启动日志 `[WRN]` 中是否有 LegacyKey 告警；
2. 如果告警提示回退失败，说明 `Encryption__LegacyKey` 未设置或与历史不符 — 联系运维按 `docs/security-audit-report-2026-08-06.md 第十章 密钥迁移指南` 处理；
3. **不要直接在页面"瞎填密码保存"**，否则会用新密钥覆盖历史密文（一旦覆盖回退链路就断了）。
